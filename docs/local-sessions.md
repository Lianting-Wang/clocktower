# 本地房间会话

连接和成员分别管理。`server/rooms.js` 保存公开局面、稳定座位标识、成员凭据哈希、本局标识及已发送给各玩家的私有身份。关闭 WebSocket 只更新在线状态。全员断线时开始 24 小时计时；连接恢复后取消。清理在每次连接前及 30 秒心跳时执行，测试可注入时钟直接检查边界。

不保存完整魔典到服务器磁盘。说书人的未发布身份与标记仍在原版浏览器存储中；房间归属哈希沿用原来的磁盘文件。服务重启会丢失内存局面和私有缓存，需由说书人恢复局面后重新发送角色。

## 协议

沿用 `[类型, 内容]` 的 WebSocket JSON 格式，连接 URL、Origin 验证和 token 机制不变。

| 消息 | 方向 | 行为 |
| --- | --- | --- |
| `resume` | 双向 | 客户端请求恢复；服务器返回 `round`、`seats`、初始化和说书人在线状态。说书人额外收到公开局面 `snapshot`；玩家随后收到公开局面与自己的 `identity`。 |
| `probe` | 双向 | 原样返回随机探测标识，检测后台恢复后的失效连接。 |
| `seats` | 服务端 | 稳定 `seatKey` 和占座 `id`；无隐藏身份。 |
| `claim` | 玩家 | `{requestId, round, seatKey}`；`seatKey:null` 表示起身。兼容旧的数组请求。 |
| `claimResult` | 服务端 | `{requestId, ok, round, seatKey/error}`。冲突、局面变化、说书人离线均明确失败。 |
| `identity` | 服务端 | 仅发送给本人，含 `round`、`assigned`、当前索引和座位标识；已发身份含 `value`、`extra.bluffs`。缓存同时绑定凭据哈希与座位。 |
| `leave` / `left` | 玩家／服务端 | 主动释放自己的座位与私有缓存。 |
| `release` | 说书人 | `{seatKey}` 释放指定座位。 |
| `newRound` / `resetRoles` | 说书人 | `{requestId, round}`。换局清空整局状态；重置角色保持原版的昼夜／提名／投票设置，只清空角色相关状态与缓存。两者都会更新本局标识。 |
| `round` / `roundResult` | 服务端 | 广播本局变更及返回请求结果。 |
| `endRoom` / `ended` | 说书人／服务端 | 立即删除房间、缓存和房间归属，关闭连接。 |

角色分发沿用 `direct` 私信。内容附加 `round`，服务器验证接收人与当前占座匹配后缓存；即使玩家离线也可保存。补发不会向其他玩家或旁观者发送。旅行者仍按原版规则公开。

同一成员近期最多 512 个请求结果在房间内缓存，重发相同请求标识不会再次入座／换局；客户端未确认请求在重连时沿用原标识。过期本局的角色消息被服务端和客户端分别过滤。

普通 `gs` 和 `player` 消息不能修改已有占座，数组索引的重排使用稳定座位标识保持绑定。说书人重连先恢复服务端的公开局面和占座，再发布本地局面，避免刷新清空座位或进行中的投票。私有魔典字段不包含在恢复的公开快照内。手动 JSON 导入／导出不加入联机元数据；导入后为座位重新建立标识，现场玩家必要时重新入座和发身份。

## 手机恢复与重复页面

`pageshow`、重新可见和 `online` 合并触发一次本地探测；不使用互联网连通性作为局域网连接的前提。探测超时重建连接，失败后按 1、2、4、8、16、30 秒间隔重试，最长 30 秒。后台及恢复阶段先移除旧私有角色，收到当前本局的私有信息后才显示。

同一凭据的新页面接管旧连接。旧页面收到 `local-session-replaced` 后暂停重连，只能通过“在此接管”手动恢复。连接事件均校验当前 socket，迟到事件不能影响新连接。`pagehide` 关闭连接但保留成员；只有原版的“离开小镇”菜单触发主动离开。

同一浏览器、同一 Origin 和保留本地存储是自动恢复的前提。微信中“在浏览器打开”、不同 IP／域名及被清理的站点数据可能产生新的身份；此时由说书人释放旧座位再入座。操作系统可以终止后台页面，应用无法保证后台 WebSocket 始终在线，恢复由下一次打开页面触发。

# 钟楼魔典本地版

固定保存集石官方中文魔典的公开前端，提供独立的角色、剧本查询接口和 WebSocket 联机服务。日常使用不连接官网、集石对象存储、Google Fonts 或统计服务器。

当前内容：**205 个角色、27 个传奇角色、132 个剧本**。界面、角色说明、标记、夜晚顺序、提名投票及原有操作由官网前端提供。

## 本机启动

需要 Node.js 22 或更新版本。当前目录已包含资源和内容数据，无需重新抓取官网。

```sh
npm ci
npm start
```

打开 **http://127.0.0.1:8080/**。默认仅监听本机；按 `Ctrl+C` 停止。旧的 `/grimoire/` 链接会保留查询参数并跳转到根页面。

首次安装依赖需要网络。安装完成后，启动服务、预置内容和本地联机不需要外网。保留整个项目及 `node_modules` 即可在这台电脑断网后启动。

## 手机与异地朋友

同一 Wi-Fi 测试时，在 macOS / Linux 运行：

```sh
HOST=0.0.0.0 npm start
```

手机访问 `http://电脑的局域网IP:8080/`。只有访问得到该地址的设备才能加入；`127.0.0.1` 指设备自己，不能作为发给朋友的远程地址。

异地联机需要将同一套程序部署到可访问的服务器。此项目已提供 Docker 和 HTTPS 配置，**当前没有配置公网、域名或隧道**。语音继续使用你们自己的语音工具。

### Docker 本机启动

```sh
docker compose up -d --build
docker compose ps
docker compose down
```

当前 Compose 将 `8080` 映射到宿主机，局域网设备可使用宿主机地址访问。房间归属信息保存在 `room-owners` 数据卷中；普通的 `down` 不删除该卷。

### 将来部署 HTTPS / WSS

将实际域名解析到自己的服务器，开放 80、443 端口，然后在项目根目录运行：

```sh
DOMAIN=你的实际域名 docker compose -f compose.yaml -f deploy/compose.https.yaml up -d --build
```

Caddy 提供 HTTPS 并转发 WebSocket，网页、API 和联机使用同一域名。浏览器会自动使用 WSS，不需要额外开放 8081 端口。配置文件在 `deploy/` 中。

## 使用与存档迁移

1. 说书人添加座位、选择剧本、分配角色，再创建小镇。
2. 将邀请地址发送给朋友；朋友加入、坐下后，由说书人发送角色。
3. 说书人的备忘标记与隐藏身份不会出现在公开小镇中。玩家只收到自己的私有角色；恶魔的伪装只随对应恶魔的私信发送。
4. 设置菜单新增 **备份／载入状态 [B]**，打开原包已经包含的 JSON 状态窗口。可以复制当前 JSON，也可以粘贴原版格式的状态再加载。

新增备份入口是对官网界面的一个明确补充：官网包内有该窗口，但当前菜单和快捷键没有打开它的入口。菜单按本地使用需求移除了整个“集石”标签；设置中“教程”下面是“钟楼百科”。

首页已移除腾讯会议推荐语和两张品牌标志；百科各页也已移除页脚的品牌标志、社交图标及其二维码。重建快照时会保留这些界面调整。

## 线下连续游戏与手机恢复

1. 说书人用手机可访问的局域网地址打开魔典并创建小镇。在右上角 **角色** 菜单选择 **复制邀请链接**，发出形如 `http://192.168.1.20:8080/?room=abc123` 的地址。旧的 `/#abc123` 也可直接进入。
2. 玩家打开链接后点击空座位，看到“正在入座”；服务器确认后显示入座成功。被抢先占座或连接失败时会提示原因，可以重试。
3. 发放身份后可锁屏、切应用或收起手机。再次打开同一地址时，自动恢复座位和本局最后发送的角色；恢复期间不显示旧身份。说书人暂时离线时，已入座玩家仍可恢复角色；新入座需等说书人上线。
4. 下一局在 **角色 → 开始新局，保留座位** 确认。保留房间、名字、称谓、座位顺序、剧本和设置；清空角色、标记、伪装、传奇／奇遇、死亡状态、提名及投票历史并回到夜晚。随后重新分配和发送角色，离线玩家回来也只会收到本局身份。
5. 玩家菜单的 **起身／离开小镇** 会释放自己的座位。说书人点击玩家名字，在座位菜单选择 **释放座位**；或在角色菜单选择 **结束房间**，让所有人退出并清除该房间缓存。原有“重置角色”也会作废已发送的身份。

断线、刷新、关闭页面和后台休眠均不会自动起身。说书人与所有玩家／旁观者都断线后，房间在服务内存中保留 **24 小时**，到期清理；有人重新连接后重新计时。同一身份同时打开多个页面时，新页面接管，旧页面停止重连，显示“在此接管”。

自动恢复需要 **同一浏览器、同一站点地址、浏览器存储未被清理**。微信中改用系统浏览器、改变 IP／域名或清理数据会成为新身份；由说书人释放旧座位，再重新入座和发送角色。复制链接时如果使用 `127.0.0.1`／`localhost`，页面会提示改用电脑的局域网 IP。

本轮不提供电脑、服务或 Docker 重启后的完整对局恢复。更新程序应安排在两局之间；更新后所有页面刷新一次。使用说明的技术细节见 [会话协议与恢复机制](docs/local-sessions.md)。iPhone 和安卓微信真机的锁屏、切应用、关闭重开仍需按 [验证记录](VERIFICATION.md) 实测。

## 本地教程与百科

- **`/guide`**：保存官网教程 HTML、CSS 和全部六张原图。默认显示魔典教程，保留说书人／玩家点击切换；原有 `type=1`、`bIsWM` 参数也可使用。
- **`/wiki`**：保存钟楼百科全部公开正文、文件说明页和上传图片，保留原版 Pivot 皮肤、字体、响应式菜单、目录折叠和站内链接。当前目录包含 432 个正文页面（含重定向）、281 个原始上传文件，以及文件说明等共 718 个公开页面。文章仍可通过 `/wiki/index.php?title=角色名称` 直接访问。
- 百科标题联想、精确标题跳转、正文搜索和结果分页在本地执行。搜索使用本地索引，排序可能与官网数据库搜索不同。

百科是采集时的**只读阅读快照**；不实现登录、编辑、历史版本或提交到官网。侧栏的最近更改等页面保留采集时内容。站外视频、社群及其他网站的主动跳转仍是外部链接。

两者与魔典共用同一个端口，无需另开 8081。`snapshot/content-manifest.json` 记录教程／百科来源、目录、采集时间、原始与本地产物的 SHA-256。快照可在断网时重建。

源站有一份失效的教程安装图标清单和三个失效的 MediaWiki 核心图片路径：前者使用教程自己的原图修复，后者使用官方 MediaWiki 原始文件。另有 411 个旧浏览器 PNG 回退地址，改用同一原版 CSS 规则中已经内置的 SVG；现代浏览器原本显示的也是这些 SVG。所有处理均记录在该清单的 `sourceIssues`，并保留原皮肤资源。

浏览器本地存档保留座位、角色、标记、伪装、自定义剧本等原版保存的内容。官网的浏览器存储无法被另一个域名直接读取，需要手动导出／导入；没有可导出的旧存档时，需要重新建局。

**固定使用同一个地址和浏览器资料**：`localhost`、`127.0.0.1`、局域网 IP 和正式域名各自拥有独立的浏览器存储。说书人身份凭据也保存在该浏览器中，不包含在对局 JSON 里。迁移到新地址或设备时可加载对局并使用新房间号。

服务端保存运行期间的公开局面和已发送的私有角色，不提供账号或云存档。服务重启后，由说书人浏览器恢复原版保存的数据、重新发布并再次发送角色。原版未保存的进行中投票和部分临时界面状态不会被 JSON 备份恢复。

## 独立联机行为

- 一个房间同时只有一个说书人连接；同一身份刷新时，新连接接替旧连接，其他身份不能接管。
- 断线保留占座；身份缓存仅向持有相同凭据的本人补发。全员离线 24 小时后清理内存房间。
- 玩家只能修改自己的称谓、认领空座位、为自己的座位投票。投票锁定和死亡票由服务端再次检查。
- 支持 20 个座位，单房间最多 64 个连接（含说书人与旁观者）。
- 浏览器身份凭据不写入邀请链接，也不输出到日志。服务端仅保存房间归属凭据的哈希；该房间停止使用 7 天后释放。
- 房间号仍采用原版的最多 10 位英文和数字。知道房间号的人可以加入旁观，未新增账号或房间密码流程。

## 快照、完整性和源站缺图

`snapshot/manifest.json` 记录来源、采集时间、原始及本地 SHA-256、大小和修复记录；`snapshot/files/` 保存按内容哈希命名的原始文件。原始 API 响应也另行保存，并记录请求参数和校验值。`public/` 和 `data/` 是本地运行用的产物。

```sh
npm run audit          # 全部原始／本地文件完整性和资源引用，不访问外网
npm run rebuild        # 仅用已保存的原始文件重建，不访问外网
```

快照没有后台自动更新。以后需要更新时，先停止服务并备份整个项目，再运行：

```sh
npm run snapshot -- --refresh
npm run audit
npm test
```

采集工具只依赖 Python 3 标准库。补丁对关键官网代码位置有断言；官网结构改变时会报错，需要检查补丁，不会假装已兼容新版本。重建后重新启动服务并刷新浏览器。

原站的一部分资源本来已经失效。本次记录并处理了：

- 7 个网站／manifest 图标路径问题，改用原站同目录中的有效图标。
- 22 个角色图片链接问题，使用已获取到的同角色图片或正确大小写的图片。
- 2 个备用剧本封面链接问题，使用剧本库对应封面。
- **55 张自制角色图标无法从源站取得**，使用有效的透明 PNG 占位，保留角色名称、能力及玩法。没有凭空补画或声称恢复了这些原图。

具体 URL、错误和替代来源见清单中的 `sourceIssues`。所有本地引用均有对应文件；这些占位不会继续请求失效的外网地址。

独立剧本编辑器、社群链接和语音平台仍是外部工具。教程和百科已在本地提供。用户主动输入的远程自定义图片、背景或剧本 URL 也可能需要外网与目标站点的 CORS 支持。自定义 JSON 文件可直接从本机导入。

## 配置与验证

| 变量 | 默认值 | 用途 |
| --- | --- | --- |
| `HOST` | `127.0.0.1` | 监听地址；Docker 内为 `0.0.0.0` |
| `PORT` | `8080` | 网页、API、WebSocket 共用端口 |
| `STATE_DIR` | `.state` | 房间归属哈希的持久化目录 |
| `ALLOWED_ORIGINS` | 空 | 额外允许的完整 Origin，逗号分隔；同源默认允许 |
| `OFFLINE_ONLY` | `0` | 设为 `1` 时，通过 CSP 禁止浏览器加载外部资源和建立外部连接 |

健康检查：`GET /healthz`。本地兼容接口：`POST /ct/grimoireRoleJson/`、`POST /ct/grimoire_edition_list/`；WebSocket：`/ws/房间号/玩家ID或host`。连接身份由本地适配器自动附加，无需用户输入。

```sh
npm test
npm run audit
npm audit --omit=dev
```

自动测试覆盖接口完整内容、分页搜索、隐私分发、权限和投票、20 玩家、重连及异常消息。浏览器验证和实机验证的区别、截图与未验证项记录在 [VERIFICATION.md](VERIFICATION.md)。
